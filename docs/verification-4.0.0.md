# 4.0.0 权限迁移验证

日期：2026-10-26。

## 原因与方案

3.x每轮释放组件会话，下一轮重新runas，重复弹窗是该生命周期的必然结果。4.0由完整安装器一次性授权固定受保护任务，界面普通权限运行，按需调用任务；不关闭UAC，不让可写GUI成为高权限任务动作，也不增加常驻服务。

授权任务限定当前SID、InteractiveToken、HighestAvailable、无触发器、固定组件与参数模板、无强制执行时限和单实例。所有者为Administrators；普通用户只有读/运行权限。GUI在运行前核对任务配置、ACL及组件受保护路径，连接后核对实际映像、SID、会话和提权令牌。

## 本机已完成的检查

- 核心66组和隔离界面188项检查通过；未改变手动三步、自动门槛、圆盘或语言行为。
- 普通权限调用者连续三次连接已有受保护组件，双向认证通过，CallerAdmin=false、Sessions=3、CommandsSent=0，没有调用runas。此阶段组件仍为3.x，验证的是不变的协议与任务调用通路，不能冒充最终4.0安装包验收。
- 合成ACL用例覆盖普通用户全控、普通用户所有权、Everyone运行和缺失用户运行权。真实普通令牌修改任务ACL被Windows以0x80070005拒绝；该异常在.NET中可能映射为UnauthorizedAccessException，验收按HRESULT识别。
- 安装脚本动态COM注册在本机失败，独立Windows调用可成功。未通过删除ACL检查或放宽权限绕过；任务注册改由受保护原生组件的固定入口负责。任务配置原生实现已在提权诊断进程实测通过。探索中的脚本/早绑定原型不进入正式安装逻辑。

## 发布门禁与边界

最终4.0组件需同提交Native AOT编译、自测、任务注册/权限/移除及认证检查。本机完整覆盖安装后需重新核验连续连接、任务启动、设置保留及公开附件哈希。托管CI若处于session 0，只验证授权任务配置并在已提权隔离进程中验证认证，不冒充真实桌面免UAC任务测试。

未重启系统、未运行本机卸载、未执行本机全系统清理或性能基准；这些不能由只读认证或模拟界面检查代替。没有承诺杀毒零误报、固定释放量或普遍提速。
