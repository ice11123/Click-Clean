# 2.3.0 本地验收记录

日期：2026-10-03。此记录是本地构建与诊断证据，不代表版本已公开发布，也不代表杀毒厂商认证。

## 界面与交互

应用 `emil-design-eng` 与 `animate` 指导，结合 Astra 重构。参考 [Twinkle Tray](https://github.com/xanderfrangos/twinkle-tray) 的快捷工具组织与 [PowerToys](https://github.com/microsoft/PowerToys) 的设置职责分离；官方资料已读取，但参考界面的浏览器截图查看受工具安全检查阻止，不能声称已逐图对比。

最终预览构建成功，界面诊断通过 **180 项自动化断言**。包含两主题、440×560 窄窗口、默认高级折叠、更新提示与最近结果同屏、主操作正常尺寸、文字对比度、折叠标题双向绑定、自动设置输入启停、三个不同作者图标与准确地址、设置焦点遍历、减少动画和桌面岛生命周期。断言数包含 50 次焦点遍历，不是 180 项独立用户场景。

主任务实际查看本地浅深色、窄窗口、设置、历史与更新提示截图；首轮发现深色默认圆圈展开箭头，改为平面细线箭头后重新编译和诊断。设置/历史的页面切换取消缩放，只保留指针触发的短透明度过渡；键盘切换即时响应。

产物目录：工作区 `outputs/Click-Clean-2.3.0-ui-red-final`，其中 `verification.json` 记录断言与测量，PNG 使用明确模拟数据，不是实际释放内存证明。100%～200% 图片由离屏倍率渲染生成，不能代替真实 Windows DPI、多屏和第三方任务栏验收。系统高对比仍需对应真实系统环境补充检查，未为测试修改系统设置。

截图诊断进程在隐藏主窗口、桌面岛收起且实际监听鼠标时，约 30.02 秒采样的整机归一化 CPU 为 0.057%，工作集 157.52 MiB，私有内存 116.79 MiB。该进程已经历多倍率截图与模拟测试，包含图像分配，不能当作正式程序冷启动或稳态内存指标。诊断完成后自行退出。

## 内存策略与更新

Core 的 **33 组测试**通过，覆盖 7 种高级组合、3 个失败位置、并发保护、取消、权限恢复、保守压力门槛、旧设置迁移、自动周期跳过、即时与延迟复测、零与负值、观测异常分离及历史兼容。诊断注入模拟更新服务，验证首页自动检查但不自动下载、点击才下载、下载完成仍不自动应用、再次点击才重启更新，以及忙碌与失败状态。

已通过真实 `WindowsMemoryApi.Read` 的 10 次只读采样，公开系统缓存、分页池、非分页池计数存在且有效；未调用真实系统整理接口。系统缓存包括待机与系统工作集，不能当作纯待机或可释放收益。

本轮没有进行真实全系统整理、安装/覆盖安装/卸载、真实账户启动任务或真实更新替换，也未修改已安装 2.2.0 的设置和历史。新增逻辑测试与旧版本既有实测不能混称为本版完整系统验收。详见 [Astra 有效性评估](memory-effectiveness-astra-2.3.md)。

当前已安装旧版的自动下载设置不受本地改版立即影响。仅安装并运行新版后，旧自动下载与自动应用字段才迁移为关闭。避免旧版自行下载，用户可以先在旧版设置关闭自动下载；本轮不自动安装，也不为展示效果改变用户选择。

## 交付边界

安装包、便携包、GPL-3.0-only 源码及 SHA-256 由 `build.ps1` 构建。未包含下载执行脚本、新 UI 依赖或签名私钥。当前包仍未进行 Authenticode 签名，哈希只用于核对文件内容，不证明发布者身份；不要求关闭杀毒或绕过 UAC。包构建/更新传输校验的最终状态以构建目录对应日志为准。
