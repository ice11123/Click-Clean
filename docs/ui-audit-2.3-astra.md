# Click-Clean 2.3 UI 简化审计（Astra）

基于 2.2.0 的真实 WPF 源码、`DockStatus`、`IslandMotion` 和 `DockVerification` 审计；应用 `emil-design-eng` 与 `animate` 技能。用户否定上一版大数字卡与通栏按钮后，本轮重新组织首页、设置、历史和页脚，定位为紧凑桌面工具。版本号只是本轮设计文档标识，不表示已经发布 2.3。

参考依据为 [Twinkle Tray 官方网站](https://twinkletray.com/) 中“从托盘立即访问功能、跟随 Windows 外观与主题”的组织原则，以及 [PowerToys 官方通用设置说明](https://learn.microsoft.com/en-us/windows/powertoys/general) 中“按外观、启动、更新分组，并表达检查、下载、就绪和错误状态”的组织原则。对应开源项目为 [Twinkle Tray](https://github.com/xanderfrangos/twinkle-tray) 与 [PowerToys](https://github.com/microsoft/PowerToys)。本轮读取了官方页面文字，但未成功查看其具体界面截图；没有复制品牌图标、视觉资产、布局源码或自动更新策略。Click-Clean 仍遵守用户要求：自动检查，手动下载，手动重启更新。

## 结构与状态契约

`HomeUpdateBanner` 为 `Border`，默认 `Collapsed`；`HomeUpdateText` 为 `TextBlock`；`HomeUpdateButton` 为 `Button`，绑定 `HomeUpdate_Click`。主窗口状态代码负责仅在更新可用、下载中、就绪、失败时显示，并决定按钮标题及可用状态。检查中和无更新不占首页空间。此审计的 XAML 不执行下载或应用更新。

保留所有原有 `x:Name` 和已有事件连接。`DownloadCheck`、`ApplyHiddenCheck` 只作为兼容命名保留且隐藏、禁用；实际禁止自动下载/应用必须同时由更新状态逻辑保证。

本轮没有更改 Core、Windows 公共 API、清理效果或压力判断；设计改动限于 `MainWindow.xaml`，局部按钮模板在窗口资源内定义，不影响其他窗口。`Header`/`Footer` 仍为 `Grid`，`MainContent` 仍为 `ScrollViewer`，`Overlay`/`ResultCard`/`HomeUpdateBanner` 仍为 `Border`，`Options` 仍为 `Expander`。局部按钮圆角为 4 DIP，没有引入新的动画或依赖。

用户追加的保守策略同时体现在主按钮、状态说明、岛的辅助名称及自动设置中；高级手动入口保留原三项选择。`FullAutoCheck` 禁用以兼容旧命名，旧策略是否暂停、压力判断及保存确认由主任务的真实状态逻辑处理，不能仅依赖禁用控件。

`MiniIsland.IsWorking` 接受主窗口真实整理生命周期；岛自身点击期间也通过 `invoking` 表达忙碌。`BackgroundMotionActive` 反映局部背景对象是否仍附带动画，用于验证收起/减少动画后的资源释放。`StatusLabel` 固定宽 126 DIP，使用等宽数字，不滚动数字。可见胶囊保持 184×36 DIP，宿主保持 216×72 DIP。

## 主题资源

| 资源 | 浅色 | 深色 | 高对比 |
| --- | --- | --- | --- |
| `Bg` / `Surface` | `#F5F2EC` / `#FFFFFF` | `#000000` / `#0D0D0D` | 系统窗口色 |
| `Text` / `Muted` | `#16243C` / `#53647A` | `#FFFFFF` / `#B8B8B8` | 系统文字色 |
| `Accent` / `AccentText` | `#A62E3A` / `#FFFFFF` | `#B74454` / `#FFFFFF` | 系统高亮/高亮文字色 |
| `Tint` / `Line` | `#F6E8EA` / `#E0DAD2` | `#2A1117` / `#343030` | 系统控件/文字色 |
| `DetailAccent` | `#96641F` | `#FFFFFF` | 系统窗口文字色 |
| `IslandBg` | `#FEF8F3` | `#000000` | `SystemColors.WindowColor` |
| `IslandText` | `#16243C` | `#FFFFFF` | `SystemColors.WindowTextColor` |
| `IslandBorder` | `#D8B784` | `#55202A` | `SystemColors.WindowTextColor` |
| `IslandHoverBorder` | `#A62E3A` | `#B74454` | `SystemColors.HighlightColor` |
| `IslandGlow` | `#E9BE6C` | `#74212F` | 使用系统强调色资源，但背景渐变隐藏 |

以上方案由主任务统一写入主题资源；系统模式先解析系统浅/深状态，再复用同一组资源。浅色的金色只用于小芯片标记和更新侧线，主数字使用深蓝；深色主题采用纯黑、暗红与白，导航选中前景使用 `Text` 白色。原蓝色应用图标按用户要求保留。渐变椭圆只在胶囊左侧局部出现，采用径向透明度遮罩，不改变文字色。

静态颜色核算：主按钮白字对红底，浅/深分别为 6.83:1 / 5.29:1；浅色金色对白底为 5.07:1。深色暗红字对暗红浅层仅 3.33:1，因此不用于导航小字；白字则为 17.63:1。岛边框对岛底约为 1.81:1 / 1.63:1，仅承担装饰，不作为唯一状态提示。文字、状态标签及键盘焦点框保留独立可见性。

## 动效参数与生命周期

| 交互 | 属性与工具 | 参数 | 停止条件 |
| --- | --- | --- | --- |
| 靠近浮出/离开收回 | 既有 `IslandMotion`，`TranslateTransform.Y` 与 `Opacity` | 150 ms，`KeySpline(0.23, 1, 0.32, 1)`；48 DIP 收回距离 | 减少动画、系统禁用动画或高对比时立即到终点 |
| 指针按下反馈 | 既有 `IslandMotion`，`ScaleX/ScaleY` | 120 ms，1 ↔ 0.97；同一 ease-out | 键盘、减少动画、系统禁用动画、高对比不播放位移动画 |
| 浮出局部渐变 | WPF 原生 `Opacity` 关键帧 | 180 ms，0 → 0.16；`KeySpline(0.23, 1, 0.32, 1)` | 完成后主动移除时钟；收起/禁用/减少动画/高对比时立即移除 |
| 整理中局部渐变 | WPF 原生 `TranslateTransform.X` | -10 → 10 DIP，1200 ms 单程，往返；`KeySpline(0.77, 0, 0.175, 1)`；透明度固定 0.24 | 整理结束、收起、禁用、减少动画、系统禁用动画、高对比或释放窗口时移除 |
| 内存压力呼吸灯 | 既有 WPF 原生 `Opacity` | 0.4 ↔ 1，1200 ms 单程、往返；按既有压力分档颜色 | 收起、未知采样、禁用、减少动画、系统禁用动画、高对比、释放窗口 |
| 整理结果 | 既有独立状态与结果计时器 | 展示 2 秒后恢复最新内存占用 | 收起后停止结果计时器，结果期限仍由状态模型决定 |

动效门槛：靠近入口属于较高频操作，只用短过渡；整理状态属于偶发状态提示。1200 ms 循环仅用于状态背景和既有呼吸灯，不用于延迟交互响应。没有增加动画库，没有动画化布局尺寸、文字内容或渐变色值。

## 验证边界

本轮重设计已完成 XAML 的 XML 解析，以及与 Git 原版的 `x:Name` 比对：未删除旧名字，新增名字用于局部控件模板及首页更新的三个命名元素。`dotnet build App/ClickClean.csproj --no-restore -v minimal` 已通过：0 警告、0 错误，耗时 9.23 秒。`git diff --check` 通过。默认大小/更新横条/结果同屏的离屏截图、减少动画与高对比状态断言由主任务统一执行，最终结果应以主任务生成的诊断证据为准；上一版 158 项 UI 断言不能代替本轮布局验证。

主任务实际检查首轮截图，发现深色 Expander 的默认白色圆圈问题，随后新增局部折叠控件模板，保留 `IsExpanded` 双向绑定、原 Header/Content 和键盘聚焦状态。最终编译发现模板无法以 Trigger 寻址内部 RotateTransform，主任务改为直接切换 Path 几何方向，重新编译成功；最终 180 项断言通过并再次检查本地截图。主任务同时将平面页面的切换由缩放改为轻量透明度，避免继续表现为大弹卡。这里记录的是主任务的截图观察与验证，不声称子任务已亲自看到截图；最终证据及边界见 [本地验收记录](verification-2.3.0.md)。

原诊断要求首页必然滚动，该断言不再符合本轮目标：应验证默认收起高级设置时无滚动，展开后在受限高度能够滚动访问全部内容。离屏 100%～200% 渲染不等同于真实显示缩放，也无法证明多屏鼠标、真实显示器文字锐度和动画流畅度。未执行真实内存整理、安装、发布或真实数据清除。局部渐变的观感仍需实际显示器以正常速度及 2～5 倍慢放检查，尤其关注文字对比度、浮出中途反向和整理结束瞬间。
