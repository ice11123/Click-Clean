# 2.3.1 原版规则恢复验收

日期：2026-10-03。本版按用户新要求恢复原版清理规则，不再沿用2.3.0保守默认策略。该记录是本地验证，不代表已公开发布或已替用户安装。

## 实际行为

- 首页、托盘与底部岛统一执行命令2、3、4：裁剪全系统工作集、刷新修改页、清理待机缓存；手动操作不受占用阈值限制。未知或无效快照仍停止。
- 自动默认阈值55%，输入、验证、存储范围55～98%。自动开关默认关闭；阈值持续60秒、30分钟冷却、5个百分点迟滞、定时低占用跳过、并发与连续失败保护保留。达到门槛的自动整理也是原版三步。
- 新安装高级选择默认为三项，旧高级选择及空选择保留；高级选择不改变快捷入口。
- 已有阈值不静默覆盖。schema4将旧版已开启的自动配置标为待确认，保存启用规则时显示裁剪与刷盘代价，确认状态持久保存。无schema的旧文件同样迁移确认，不能误判成新安装。
- 更新仍由用户手动下载和重启，未恢复自动更新。

## 回归证据

先添加“手动低占用也执行三步”的回归断言，在2.3.0代码上失败，证实旧入口直接跳过。这里是已知产品策略的反转，不是假定系统API失效；无需臆造硬件或权限故障来解释结果。随后修改策略与范围验证，并同步应用入口。

Core最终通过 **38组测试**，覆盖原有7种自定义组合、3种失败位置、权限恢复、取消、并发、即时与复测，新增55%边界、低占用手动三步、默认开关关闭、55%持续时间及50%重新武装、旧配置确认、保留旧阈值与无schema迁移。

诊断程序最终通过 **190项界面断言**，包含原有浅深色、100%～200%离屏渲染、窄窗口、键盘焦点、桌面岛、手动更新，以及实际应用执行入口的模拟验证：

- 低占用和高占用手动操作均按2/3/4调用，重复点击不并发。
- 待确认自动配置不执行；自动低于55%不执行，达到55%执行三步。
- 界面拒绝54而不保存，不意外开启自动规则；55能够保存且清除待确认；关闭规则后确实停用。

自动入口验证通过反射调用源码中实际的私有RoutineCleanup方法，使用注入的模拟API，不另写一个假业务实现。截图明确标注模拟数据，数字不是本机实际释放量。证据位于工作区outputs/Click-Clean-2.3.1-ui-check/verification.json与对应PNG。断言总数包含50次焦点遍历，并非190个独立场景。离屏倍率不等同真实Windows显示缩放，高对比及特殊任务栏仍需对应环境验收。

隐藏采样诊断的约30.03秒整机归一化CPU为0.029%，工作集157.54MiB、私有内存114.80MiB；含前置截图分配，不代表正式软件稳态占用。诊断进程自行结束。本轮未进行真实内存整理、安装/卸载、计划任务变更或真实更新替换，未修改当前安装及用户数据。

## 效果边界

原版三步确实恢复了更强干预，而不是改写统计数值。但裁剪不等于释放全部应用分配：页面之后仍可能重新进入工作集，修改页也需要写回；更多可用内存不能证明程序提速。参见[微软工作集说明](https://learn.microsoft.com/en-us/windows/win32/memory/working-set)。待机列表本来就计入可用内存，参见[微软性能计数结构说明](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-performance_information)。

55%是用户指定的触发参数，不是系统低内存通知。正常使用也可能达到这一比例，因此自动开关仍默认关闭，不默默把旧温和规则升级成自动刷盘。保留返回码、即时/复测、负值与观测错误，而不是承诺每次固定释放或更快。

安装包仍未签名。最终包构建与更新传输验证状态以输出目录相应日志为准；未覆盖旧版发行资产。
