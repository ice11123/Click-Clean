# Click-Clean 使用说明

Windows 11 x64内存整理工具，简体中文 / English。原作者：离子怪（ice11123）。

## 下载与启动

从[官方发行页](https://github.com/ice11123/Click-Clean/releases/latest)下载。新安装默认浅色、开启底部整理岛、关闭自动整理及登录启动；首次可选择语言。设置中可随时切换语言、主题和岛，更新保留偏好。

安装程序申请管理员权限，软件界面和日常回收不申请。关闭窗口默认进托盘；托盘支持打开、优化、显示岛和退出。登录启动采用当前账户普通权限任务。

从2.x迁移3.0建议先正常退出旧实例，再运行安装包，部署受保护高级组件并迁移旧最高权限任务。便携包解压完整目录运行`current/ClickClean.exe`；没有受保护组件时，监测和日常回收仍可用，高级操作需安装版。不要从可写目录直接以管理员运行软件。

脚本可用`current/ClickClean.exe --exit`请求安全退出，不强制结束系统调用。

## 整理与自动化

日常入口先检测Windows真实低内存信号；正常、矛盾或未知状态保留原状。只有实际压力下才尝试整理持续闲置的当前用户后台，不干预前台、关键或交互中的应用。

后台需至少60秒闲置观察；单轮最多3个进程、驻留预算768MiB。每次执行前重查身份与活动，压力解除即停；有目标冷却与快速回涨/缺页避让。不结束进程、不释放应用私有分配、不修复泄漏。驻留减少不是性能提速证明，后台恢复时仍可能重新访问页面。

高级手动保留原版三步：裁剪全系统工作集、刷新修改页、清理待机缓存。它们可能增加缺页、重新加载或磁盘活动，必须明确选择和确认，并通过UAC交给受保护组件执行。每步失败即停，取消只阻止后续步骤。

| 自动设置 | 默认 |
| --- | --- |
| 压力/阈值触发 | 关闭；持续60秒 |
| 定时检查 | 关闭；60分钟 |
| 触发依据 | Windows低内存通知 |
| 百分比检查参数 | 55%；不能替代真实低内存信号 |
| 冷却 | 30分钟 |
| 全屏与磁盘忙碌避让 | 开启 |

所有自动入口仍需实际压力与闲置准入；定时不是定时强清。旧自动规则升级后需重新确认，既有阈值不被无声改写。软件退出后不会自动整理。

## 界面与结果

首页只呈现短压力状态、主操作与最近结果。正常或无对象时显示“无需整理”，未知状态明确说明；不显示虚构提速百分比。详细步骤、原始错误码、可用及提交读数放在详情。

底部岛位于主屏任务栏中央上方，靠近浮出、点击进入相同日常流程；成果保留2秒后恢复实时内存数。数字按实际读数显示，呼吸灯占用分档不是性能评分。主题跟随应用，减少动画、高对比、收起时停止循环。可见采样1秒、隐藏10秒；后台闲置只读观察低频进行。

实际执行后约3秒复测、30秒持续观察仅记录读数，不再调用整理。零、负值和未知均保留；其他系统活动也会影响结果。诊断页按需观察进程私有增长，离页停止，不把增长直接叫作泄漏。

## 更新与数据

默认首页自动检查，此后约6小时检查一次。发现更新醒目提示，但只有点击才下载，下载后还需点击重启应用。普通界面更新不需安装向导；涉及高级组件的特殊迁移使用安装包，不从可写更新缓存提权安装。2.x旧客户端无法预先识别3.0组件迁移，建议直接安装新版。

设置、最近30条记录和诊断日志位于`%LOCALAPPDATA%/ClickCleanData`。升级保留语言等偏好，卸载可选择保留。日志留在本地，分享前请检查个人信息。当前发行包未签名；正常使用不需要关闭杀毒或绕过UAC。

## 从源码构建

需要.NET SDK 10.0.301（允许的补丁版本）、Windows构建环境、完整安装包所需Inno Setup 7；Native AOT高级组件还需微软C++工具链。无工具链时，可从同一源码提交的GitHub CI下载产物，经构建脚本验证后输入。

```powershell
.\build.ps1 -OutputRoot .\dist -PrivilegedPublishDir .\verified-component -IncludePreview
.\build-x86-experimental.ps1 -OutputRoot .\dist-x86
```

没有安装器可加`-SkipInstaller`，只生成普通权限便携与更新包。代码签名需真实受信任证书，见[签名说明](signing.md)。

Diagnostics预览使用模拟数据，不代表实机效果。`--controlled-memory-experiment 输出文件`只裁剪本次创建的128MiB子进程，验证原生行为与再次访问代价，不干预其他应用；不是全系统性能基准。`--memory-read`和`--read-environment`只读；`--system-check`是独立的真实高级三步诊断入口，不应无意运行。
